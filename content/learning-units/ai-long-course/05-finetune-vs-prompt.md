---
concept: 微调 vs 提示词
question: 什么时候应该微调，什么时候提示词工程就够了？
definition: 提示词工程通过修改输入引导通用模型输出，零训练成本但能力上限受限于基模。微调（SFT/LoRA/RLHF）让模型习得新分布，能力天花板更高但需要数据、算力和评估能力。
mechanism: 任务可被自然语言精确描述 → 提示词足够；输出格式严格、领域知识深、风格定制 → 微调更稳。RAG 解决知识更新，微调解决能力定制。
example: 法律合同审查可用提示词 + RAG；客服对话风格统一、特定推理链路必须微调；GPT-4 写广告文案提示词搞定，写公司内部邮件风格需 LoRA。
misconception: 不要默认上来就微调（成本高、迭代慢、容易过拟合），90% 任务提示词+RAG 解决。
practice: 选一个真实任务，先用 GPT-4 + 5-shot prompt 测，准确率 < 80% 再考虑微调。
reviewPrompt: 决定微调前问：提示词的 context 真用满了吗？
